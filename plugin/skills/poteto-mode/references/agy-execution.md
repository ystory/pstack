# Antigravity workers

Read this reference for every resolved `executor: "antigravity"` seat. The launching host's role helper remains the selection authority. An Antigravity entry supplies an exact `model` and separate `reasoningEffort`. Preserve ordered seats and duplicates. Parent aliases stay on the native parent. Each new seat or round gets a fresh run directory and native agy conversation.

Launch the foreground runner through the launching host's asynchronous command controls. Keep the command attached until its terminal result. Do not shell-background or detach it.

```sh
node "<poteto-mode>/scripts/run-agy.mjs" run \
	--cwd "/absolute/assigned-worktree" --run-dir "/absolute/unique-local-run" \
	--model "<selected-exact-model>" --effort "<supported-effort>" \
	--role "/absolute/original-role.md" \
	--instruction "/absolute/project/AGENTS.md" --skill "/absolute/relevant/SKILL.md" \
	--prompt-file "/absolute/consolidated-task.txt"
```

On Codex, use the exposed command and session controls. Request reviewed escalation with a task-specific justification when the host sandbox blocks required existing runtime access. On Claude Code, use native background Bash with `run_in_background: true` and `timeout: 7200000`, the limit the Codex runner uses. Track the host command identity and collect its terminal receipt. Set `--timeout-ms N` only when the task itself has a deadline. The request and receipt record it as `timeoutMs`. Stop through the host's actual process controls and collect the resulting receipt. Signal delivery alone does not prove closure.

Pass the complete consolidated brief, assigned checkout, ownership, constraints, expected result, and artifact paths. Repeat `--instruction` for project rules, templates, rubrics, and references, and `--skill` for skill bodies. Use `--role` for the selected original agent body. A general-purpose seat has no added role body. Pass the absolute poteto-mode skill for a poteto-agent. The runner embeds these complete files and the shared [receiving-worker context](worker-context.md). Linked references and principle leaves still require complete supplied bodies or actual reads.

The runner uses the official agy CLI version 1.5.8 or newer. Workers use subscription login or ADC. Setup prepares only selected executors and the authentication method the user chose. The worker inherits that method through the existing official CLI environment and settings. The runner passes no authentication option and removes `GEMINI_API_KEY` and `GOOGLE_API_KEY` from the worker's environment. The receipt's `auth.method` names the method. It is `gemini-api-key` when agy's settings set `modelProvider` to `gemini`, otherwise `adc` when `AGY_ADC_AUTH=true`, otherwise `inherited-default`. `gemini-api-key` is the Gemini API-key route, which workers do not use. Under it the runner starts no catalog or worker, and the run receipt's `stop.code` is `unsupported-auth` with a cause that names the setting. `auth` also records the `modelProvider` value and whether the runner's own environment has `GEMINI_API_KEY`, never the key. `verified: false` means no authentication probe ran. Do not read or copy credentials, change authentication methods, or save personal defaults. A missing executor remains a capability gap.

The runner passes `--dangerously-skip-permissions`, so agy approves every native tool request. Headless agy cannot ask for a permission, and a request that no rule allows would end the run with no answer. A tool error, such as a read of a missing file, returns to the worker, and the receipt lists it in `toolErrors`. The run continues. Approval is not an OS boundary, so a read-only task stays read-only only through its brief. Check `git status --short` before and after it. The worker uses agy's native tools and customizations. It does not inherit the parent's MCP inventory, complete conversation, native subagent controls, or permissions. Keep a required missing capability as the calling workflow's gap.

Preserve the exact model ID and selected effort. A catalog label with a fixed effort confirms only that variant's configured availability. It does not prove inference or support for other efforts. Use each model's source-labeled capabilities for adjustments. If no supported effort is at or below the requested budget, report the required choice. Never switch model IDs or authentication routes silently. Keep rejected settings by executor, exact model, and effort. Never resubmit a rejected setting. Follow the caller's supported starting-effort retry or existing fallback rules with disclosure.

Inspect `result.json` and `final.txt` in the run directory. Host stdout can truncate. Requested model and effort, CLI-observed model, and effective effort are separate evidence. The CLI does not separately report effective effort, so that value remains unknown. Native usage is conversation-cumulative. Do not add resumed usage to prior totals or describe it as current-turn usage or settled billing. Only a completed receipt with matching init and result conversation IDs, one successful or recovered terminal result, a nonempty response, and orderly zero-exit process closure establishes success. When agy exits, its process group goes with it. `process.descendantsReaped` is true when processes agy started outlived it and were killed, and null when no supervisor report arrived. A recovered result has status `ERROR`, finished reason `error`, and the last model error that agy retried during the turn, such as a 429. agy exits 0 after it, and a completed receipt keeps that error in `recoveredError`. A late apparent success cannot override an error, cancellation, or timeout. A failed receipt keeps the native terminal result, including its status, error, finished reason, and usage. Review files and verification evidence under the calling workflow's own rules.

The receipt's `stop.kind` names how the run ended. It is `completed`, `interrupted` for a deadline or a signal, or `error`. `stop.continuable` is true when the receipt proves the exact conversation identity, delivered task input, and a closed process group. Continue a stopped run per [Continuing a stopped worker](continuation.md). Pass `--resume /absolute/prior-run/result.json` with identical model, effort, canonical cwd, and inherited authentication method. A method change between runs blocks continuation. Each receipt permits one continuation. The runner retains a permanent `continued-by.json` edge before launch, so a second continuation from that predecessor fails even after the first finishes. The new receipt can continue once. Keep failed continuation evidence and investigate it. Never use a latest selector or a naked conversation ID, and never replace a failed continuation with a fresh worker without saying so.

The official CLI owns native conversation storage and history. The receipt does not hash that transcript or prevent direct native clients from changing it. No native host history inheritance is claimed. Antigravity entries do not install or register native parent roles.

Use known exact-model lineage for family diversity. The Antigravity executor name does not establish a family. Ambiguous custom IDs and virtual routes with unknown lineage cannot satisfy a different-family gate. Preserve the calling workflow's selected-pool rules, cardinality, fresh-worker requirements, dropout handling, required gates, and Arena's disclosed judge skip.
