# Antigravity workers

Read this reference for every resolved `executor: "antigravity"` seat. The launching host's role helper remains the selection authority. An Antigravity entry supplies an exact `model` and separate `reasoningEffort`. Preserve ordered seats and duplicates. Parent aliases stay on the native parent. Each new seat or round gets a fresh run directory and native agy conversation.

Launch the foreground runner through the launching host's asynchronous command controls. Keep the command attached until its terminal result. Do not shell-background or detach it.

```sh
node "<poteto-mode>/scripts/run-agy.mjs" run \
	--cwd "/absolute/assigned-worktree" --run-dir "/absolute/unique-local-run" \
	--model "<selected-exact-model>" --effort "<supported-effort>" \
	--role "/absolute/original-role.md" \
	--instruction "/absolute/project/AGENTS.md" --skill "/absolute/relevant/SKILL.md" \
	--allow-permission 'command(git)' \
	--prompt-file "/absolute/consolidated-task.txt"
```

On Codex, use the exposed command and session controls. Request reviewed escalation with a task-specific justification when the host sandbox blocks required existing runtime access. On Claude Code, use native background Bash with `run_in_background: true` and the task's supported timeout. Track the host command identity and collect its terminal receipt. Set `--timeout-ms N` when the task needs an overall deadline. Stop through the host's actual process controls and collect the resulting receipt. Signal delivery alone does not prove closure.

Pass the complete consolidated brief, assigned checkout, ownership, constraints, expected result, and artifact paths. Repeat `--instruction` for project rules, templates, rubrics, and references, and `--skill` for skill bodies. Use `--role` for the selected original agent body. A general-purpose seat has no added role body. Pass the absolute poteto-mode skill for a poteto-agent. The runner embeds these complete files and the shared [receiving-worker context](worker-context.md). Linked references and principle leaves still require complete supplied bodies or actual reads.

The runner uses the official agy CLI version 1.5.8 or newer. Setup prepares only selected executors. It inherits the existing official CLI environment and authentication. `AGY_ADC_AUTH=true` selects inherited ADC mode. Otherwise the receipt records `inherited-default`. Do not read or copy credentials, change authentication routes, or save personal defaults. A missing executor remains a capability gap.

Keep normal session permissions. Repeat `--allow-permission RULE` for already-authorized operations the task needs. The runner supplies these rules through agy's documented inline `--settings` object for that invocation. Use scoped rules such as `command(git)`, `command(regex:npm run (build|lint|test))`, or `write_file(src/)`. These permissions do not enforce OS read-only access. The worker uses agy's native tools and customizations. It does not inherit the parent's MCP inventory, complete conversation, native subagent controls, or permissions. Keep a required missing capability as the calling workflow's gap.

Preserve the exact model ID and selected effort. A catalog label with a fixed effort confirms only that variant's configured availability. It does not prove inference or support for other efforts. Use each model's source-labeled capabilities for adjustments. If no supported effort is at or below the requested budget, report the required choice. Never switch model IDs or authentication routes silently. Keep rejected settings by executor, exact model, and effort. Never resubmit a rejected setting. Follow the caller's supported starting-effort retry or existing fallback rules with disclosure.

Inspect `result.json` and `final.txt` in the run directory. Host stdout can truncate. Requested model and effort, CLI-observed model, and effective effort are separate evidence. The CLI does not separately report effective effort, so that value remains unknown. Native usage is conversation-cumulative. Do not add resumed usage to prior totals or describe it as current-turn usage or settled billing. Only a completed receipt with matching init and result conversation IDs, one successful terminal result, a nonempty response, and orderly zero-exit process closure establishes success. A late apparent success cannot override an error, cancellation, or timeout. Review files and verification evidence under the calling workflow's own rules.

Continue only under poteto-mode's costly-state exception. Pass `--resume /absolute/prior-run/result.json` for an exact successful closed receipt with identical model, effort, canonical cwd, and inherited authentication mode. Each receipt permits one continuation. The runner retains a permanent `continued-by.json` edge before launch, so a second continuation from that predecessor fails even after the first finishes. A new successful receipt can continue once. Keep failed continuation evidence and investigate it. Never use a latest selector, a naked conversation ID, or a fresh fallback.

The official CLI owns native conversation storage and history. The receipt does not hash that transcript or prevent direct native clients from changing it. No native host history inheritance is claimed. Antigravity entries do not install or register native parent roles.

Use known exact-model lineage for family diversity. The Antigravity executor name does not establish a family. Ambiguous custom IDs and virtual routes with unknown lineage cannot satisfy a different-family gate. Preserve the calling workflow's selected-pool rules, cardinality, fresh-worker requirements, dropout handling, required gates, and Arena's disclosed judge skip.
