# Codex execution

Read this reference before launching, steering, waiting for, or collecting pstack delegates. Resolve every bundled path from the directory containing the actual installed `SKILL.md`, not from the workspace or a guessed installation directory.

## Roles, models, and effort

Run the sibling setup helper with its absolute path:

```text
node <skills>/setup-pstack/scripts/models.mjs resolve --role "<role>"
```

It reads `$CODEX_HOME/pstack-codex/models.json`, or `~/.codex/pstack-codex/models.json` when `CODEX_HOME` is unset. The response contains `role`, ordered `entries`, `source`, and `file`. Each entry supplies `model`, its saved budget's starting `reasoningEffort`, and an optional `executor`. `"antigravity"` uses the official agy runner described below. An absent executor or `"codex"` uses native Codex delegation. `"claude-code"` uses the bundled Claude Code runner with that entry's exact model ID. Pass it explicitly as `--model ENTRY.MODEL`.

A missing role resolves to `inherit-parent` with source `unconfigured`. Scalar roles yield one entry, the two panel roles yield three initial entries, and the cross-judge pool yields two. Disclose the native-parent resolution. Saved exact choices remain authoritative. No bundled model or external CLI is required before setup.

Preserve ordered entries and their multiplicity. Equal entries remain separate executions. Saved role selections override defaults. For an explicit model, use the task's explicit effort when given; otherwise adjust the entry's starting effort for the job using poteto-mode's Subagents guidance and the selected executor's confirmed model capabilities. Pass model and effort separately. A refused model follows the caller's documented fallback, and every fallback is reported. A rejected adjusted effort returns to the role's supported starting effort and is reported. Never invent a model ID or attach effort or speed suffixes.

`auto` and `inherit-parent` both select the current native Codex parent model. Budget changes preserve these aliases. Check the active native subagent defaults and selected role before binding them: an omitted model or effort can select `[agents]` defaults, and an omitted agent type can apply the configured `default` role. Omit model and effort only when they will preserve the parent selection. Otherwise pass the observed parent model and effort explicitly through supported fields, using a fresh-context brief when the host requires it. If the parent settings or effective inheritance cannot be established, report the alias as unresolved. An alias is not a refused model and does not use a fallback model.

Keep a per-executor record of rejected model IDs during the run. A model is rejected when the executor reports it invalid or omits it from an explicit list of valid models. Never submit an already rejected model to that executor again, including through a fallback. After a rejected adjusted effort or speed, try the role's supported starting setting unless its model is already rejected, then follow the calling skill's fallback. When the caller has no fallback, use the closest valid model of the role's family from the error's list. If that list has none, or the caller exhausts its fallbacks without another outcome, bind a native execution to the actual parent selection and disclose the loss of the requested model. An unresolved parent selection remains unresolved. Explicit different-model or different-family gates still apply, as do Arena's judge skip rules. An unavailable executor is a capability gap, not evidence that a model was rejected.

Speed uses a separate executor control when one is exposed. Native subagents inherit the root session's service tier when no per-agent speed control is available. Report an urgent fast request that the selected executor cannot express independently.

Record the actual model and effort for each execution when the executor exposes them; otherwise distinguish requested settings from unknown effective settings. Validate required distinct models or families before launching the affected step; report a configuration error when the selected entries cannot satisfy it. A distinct-model or distinct-family requirement remains a requirement. Repeated seats on one model do not satisfy it. Keep a source preference distinct from a requirement and report an unmet preference accurately. Arena has its own different-vendor-or-skip rule for its judge, rather than a stop on an unavailable judge.

Required trail reviews and verifiers use eligible exact choices already resolved by the calling workflow, in their existing order, or an explicitly supplied task counterpart. Do not scan unrelated roles or add a verifier role, priority ranking, or fixed counterpart. Disclose the chosen entry and its source. Parent aliases and unknown families cannot establish a different-family or different-vendor relationship. Families follow Arena's Phase A. Fable is its own family, and Sonnet and Opus belong to the same Claude family. If no eligible counterpart can run, preserve that step's existing unmet or capability-gap outcome. Arena compares its judge's vendor with the parent's. Fable and the other Claude models are one vendor. It uses only its ordered selected pool, skips with disclosure if no eligible judge runs, and retains its unknown-parent rule. That skip does not waive another workflow's required verifier. Preserve each caller's dropout and retry rules.

## Native delegation

Inspect the tools exposed by the current runtime and use their actual schemas. Use native Codex subagent tools for entries whose executor is absent or `"codex"`, not Cursor `Task` parameters. On a runtime exposing `collaboration`:

- Spawn with `spawn_agent`, a unique `task_name`, and a complete `message`.
- The message includes the goal, owned files or slice, boundaries, exact verification, required report, and absolute skill/reference/artifact paths. For writers, say they are not alone and must accommodate others' edits.
- Read-only workflow seats, including How, use an explicit no-edits brief and the general-purpose path below; Codex does not gain a separate OS-readonly role. General-purpose workflow seats select `agent_type: "pstack-general-purpose"` when that registered role is available. Setup registers this pstack routing role with a description only, without a config file or instruction body. It preserves the parent-derived instructions and selected model/effort instead of applying the user's configured `default` role. If the role is unavailable and the resolved seat has `source: "unconfigured"`, use the host-supported native general-purpose or default path instead, including for callers that name `pstack-general-purpose`. Explicit task-native counterparts and arms keep their exact selected model and effort on this path. Bind the actual native parent model and effort only when the selected entry is a parent alias, under the parent-selection rules above. Supply the complete task brief and workflow instructions. Disclose the unconfigured seat, native role path, and requested settings. Do not infer parent inheritance from an omitted role, model, or effort. If the host cannot express that binding, report that specific capability gap. Saved selections retain the registered-role path. Inspect the actual schema and role precedence. Check effective settings when the host exposes them; otherwise record them as unknown instead of inferring missing response fields.
- Playbook delegates select the registered `poteto-agent` custom role through `agent_type`. Comment cleanup selects `comment-sicko`. Both custom roles require setup registration before use. Pass the absolute `poteto-mode/SKILL.md` path to every `poteto-agent`; its preserved instruction body uses that path to find the bundled principles. Use its complete supplied body without reopening the file. Read required bodies that are missing or incomplete, including applied principle leaves.
- Resolve custom roles through native discovery after setup. Confirm both the loaded role and a role-selector field in the actual spawn schema. If either is unavailable, inspect registration, enabled config layers and project trust, and the host's tool capabilities; report the specific gap. For an unconfigured general-purpose seat, use the native path above when it can preserve the selected model and effort. Otherwise use the authorized setup path for missing registration and start a new Codex session before retrying, as setup requires. Preserve the requested custom role's instructions.
- Explicit `model` and `reasoning_effort` overrides use `fork_turns: "none"` on schemas that require it. Supply all task context in the message. Inherited aliases use the parent-selection binding above; a fresh brief can still use `fork_turns: "none"`. A seat that its caller launches without a role, such as How's subagent or a Recall investigator, uses the parent-selection binding with `fork_turns: "none"` and a complete brief, matching upstream's clean subagent context.

`fork_turns: "all"` copies conversation history into a subagent. It does not create an independent checkout, copy uncommitted files, or clone running processes. `fork_turns: "none"` starts from the complete brief. Neither field supplies worktree isolation. Use the local-worktree and working-tree transfer rules below for filesystem state. These collaboration schemas have no worker-fork operation that copies a live environment. Use the stateful reuse exception below when the required state cannot be moved, rather than creating a separate user task to simulate a worker fork.

Launch independent seats consecutively without waiting between them. A concurrency limit affects how many run at once, not how many seats the workflow requires. Queue remaining seats and drain them; preserve every required result.

## Claude Code delegation

For an entry with `executor: "claude-code"`, resolve `scripts/run-claude.mjs` from the installed `poteto-mode` directory. Write the consolidated task brief to an absolute local file, then launch the runner through the host's command tool. The process inherits that command's OS permissions and environment. Prepare the launch for the worker's authorized task, including existing Claude authentication, runtime state, browser processes, local servers, and network access when needed. On a Codex host exposing `exec_command` with `sandbox_permissions`, request `sandbox_permissions: "require_escalated"` with a task-specific `justification` when those operations require it, and set `workdir` to the assigned checkout. Launch approval does not preapprove Claude's own tools. Supply the scoped tool rules below. If access fails, identify whether the launcher or Claude denied it before changing the assignment. Keep the actual error and approval result. Do not use another executor to bypass an explicit denial.

A task that edits `index.mjs` and verifies it with `node --test index.test.mjs` needs no tool rules:

```sh
node "<poteto-mode>/scripts/run-claude.mjs" run \
  --cwd "/absolute/assigned-worktree" \
  --run-dir "/absolute/local-run-directory" \
  --label "<short task name>" \
  --model "<resolved-entry.model>" \
  --effort xhigh \
  --instruction "/absolute/applicable/AGENTS.md" \
  --skill "<absolute/relevant/SKILL.md>" \
  < "/absolute/task-prompt.txt"
```

Use the resolved exact model ID and task effort for workflow delegates. The raw runner also accepts a self-contained prompt without context files; supplied context paths remain absolute and are read as requested. Omitted effort uses the Claude CLI default and is recorded as `null`, without a bundled fallback. Repeat `--instruction` for the applicable project instructions and selected source references, templates, and rubrics, and `--skill` for the relevant skill bodies. The runner reads these absolute files and sends their contents with the task to Claude Code. Pass these paths to the runner instead of reading and copying their bodies into the brief. The worker uses the complete supplied bodies under the [receiving-worker context rules](worker-context.md). The runner starts Claude Code with `--permission-mode auto`, so Claude's auto mode approves or denies each tool call and the caller gathers no per-file or per-command rules. A denied call appears in the receipt's `stop.permissionDenials`. Show the user the denied action. After the user's explicit approval in chat, continue the session with `--resume` and an `--allowed-tool` rule for exactly that action. Claude Code absolute file rules begin with two slashes, as in `Edit(//absolute/project/new-file.md)`. Keep task edits in the assigned cwd/worktree.

Claude Code's [file permission rules](https://code.claude.com/docs/en/permissions#writepath-notebookeditpath-and-globpath-rules-never-match) match file creation and editing through `Edit(path)`. A path-scoped `Write(path)` rule is accepted but never matches. `--allowedTools` preapproves matching calls; it does not restrict the available tool set or create a filesystem boundary. Auto mode does not create one either. An allowed shell or interpreter can perform operations beyond another tool's rule, so retain the host's OS permissions and the task's ownership scope.

The brief carries the original task, later directives, owned scope, cwd and branch, exact input SHAs, required tools and constraints, verification, artifact locations including this runner's run directory, and output contract. Filled template fields belong in that brief. Preserve judge blinding by using sanitized candidate labels and paths in the judge's files and brief.

When the original dispatcher calls for `poteto-agent` or `comment-sicko`, add `--role "<plugin>/agents/poteto-agent.md"` or `--role "<plugin>/agents/comment-sicko.md"`. Pass `poteto-mode/SKILL.md` with `poteto-agent`. General-purpose reviewers, candidates, investigators, and explainers use their own workflow sources without a `--role` file. Native role registration does not load instructions into Claude Code.

The runner invokes the existing Claude Code installation with `claude -p --model SELECTED_EXACT_ID`, the chosen effort, and stream JSON output. CLI detection reports global effort syntax, not per-model availability. Setup's model-specific source evidence remains separate from the result of a real run. `request.json.model` records the requested ID, while `observedModel` comes only from the stream and may differ or be null. Every run requires `--model EXACT_ID` and reports `modelSelection: "explicit"`. An omitted model fails before launching a worker. It uses Claude Code's existing authentication and configured harness, tools, and MCPs. The Codex parent's native role configuration, MCP inventory, and thread state do not automatically load into Claude Code.

Start each independent seat or new round with a distinct run directory and a fresh Claude session. Only the stateful reuse exception in poteto-mode permits `--resume "<exact-session-uuid>"` on a subsequent run. A stopped session's conversation meets that exception, per [Continuing a stopped worker](continuation.md). The receipt's `stop` records how the run ended. Pass the original `request.json.model` explicitly when resuming, including for a nondefault model. A running command is asynchronous work; track its command identity and collect its terminal receipt. Do not wait for one independent seat before launching the next.

The outbound runner automatically includes the shared [receiving-worker execution context](worker-context.md) in its task payload. It keeps the launching configuration authority and distinguishes native receiving tools from parent launch recipes. The task still supplies its original role, selected model and effort, scope, and permissions.

## Antigravity workers

For `executor: "antigravity"`, preserve the returned exact `model` and separate `reasoningEffort`. Read [Antigravity execution](agy-execution.md) for the official agy runner, scoped session permissions, complete context, terminal receipts, cumulative usage, and exact continuation. Use this host's asynchronous command controls and collect every terminal receipt. Antigravity entries have no native agent type. Parent aliases stay native. Use known exact-model lineage for diversity. Custom or virtual routes with unknown lineage remain unknown. Preserve the calling workflow's selected-pool, cardinality, fresh-worker, required capability, and family gates.

## Run records and progress

The Codex, Claude, and Antigravity runners record each run the way Orca records its workers. Pass `--label "<short task name>"` on every launch. Each run appends `events.jsonl` to its run directory, one JSON line per event: `started` with the executor, model, effort, cwd, label, and runner pid, `activity` for a command, file edit, or tool call, `turn-completed` with the CLI's own turn status when a turn ends, and `stopped` with the stop kind and code. Each run also writes one registry file under the pstack state directory: `$PSTACK_STATE_HOME`, else `$XDG_STATE_HOME/pstack`, else `~/.local/state/pstack`. Registration is best effort: a run whose registry file cannot be written still runs, and its receipt's `registry` holds the error instead of the run ID.

`node "<poteto-mode>/scripts/workers.mjs" status` lists the runs registered for the current directory and the directories inside it, with executor, model, label, state, and last event. A run is `running` while its runner lives without a readable `result.json`, `lost` when the runner died without one, and otherwise its receipt's stop kind. An unreadable registry entry is skipped with a note on stderr. Run it when the user asks what is running or where, and after compaction or a restart to find run directories rather than recalling them. `--cwd DIR` selects another checkout, `--all` lists every run, and `--json` prints records.

`workers.mjs follow --run-dir DIR` prints each new event and exits when `result.json` appears, or with status 1 when the runner died without writing it. Read the same output when you check a runner's command session, and tell the user which executor, model, label, and checkout each worker uses when it starts.

A receipt's `stop.code` names the cause: `completed`, `signal`, `deadline`, `usage-limit`, `not-signed-in`, `model-unavailable`, `provider`, `missing-session`, `permission-mode`, `permission-denied`, `unsupported-auth`, or `failed`. `stop.cause` holds the redacted tail of the evidence, and the run directory keeps the raw diagnostics. `not-signed-in` and `unsupported-auth` need the user's login or setup. `usage-limit` and `provider` follow the calling workflow's dropout rule. `missing-session` cannot continue. Each runner starts its CLI under a supervisor that removes the parent session's environment, runs the CLI in its own process group, and stops that group when the runner stops or dies. When the CLI exits, the supervisor kills what remains of its group, and the receipt's `descendantsReaped` is true when anything remained. The receipt's exit code and signal are the CLI's own, also when a stop ended it. A runner that received a stop signal exits 128 plus that signal's number, 130 for SIGINT and 143 for SIGTERM.

## Local worktrees

Workers run on the current host through their selected executor. Give each independent worker an exclusive Git worktree and branch when it writes code. Use native managed-worktree tools when exposed, or `git worktree add` with an explicit base ref and a local `codex/` branch. The worker's prompt names its absolute checkout, branch, and resolved starting SHA; every shell command runs in that checkout. Keep the coordinator's checkout separate.

For workflows that previously started from the repository's default branch, resolve the actual default ref and SHA before creating the worker checkouts. A caller-supplied non-default ref replaces that base. Measurements and verification pin the exact SHAs required by their brief. Local uncommitted changes enter a worker's input only when the brief explicitly includes them.

The coordinator owns worktree preparation and cleanup coordination. Inspect the native tool's caller and attachment semantics. When managed creation retargets its caller, invoke it from a native child preparation context instead of the coordinator chat. For an external worker, a short native setup child may return the ready checkout before the selected runner launches. Preserve the chosen worker executor and model. Wait for terminal creation and use the returned absolute cwd explicitly, even when the child's thread cwd stays unchanged. Check host thread and attachment state before and after preparation to confirm that the coordinator's primary checkout stays unchanged. Shell `pwd` alone does not establish this.

The coordinator manages shared repository metadata. Each branch owner performs the pushes, rebases, and PR operations its calling workflow assigns. Workers own their assigned checkout and output only. Worktrees isolate files and indexes; they share the host, repository metadata, credentials, and other machine resources. Assign distinct ports, temporary/cache/data directories, simulator/device resources, and output locations for work that uses them. Serialize a machine resource that cannot be separated. Restrict the brief's commands to the assigned resources.

Before a worker runs in a new worktree, prepare its dependency and build directories per [Worktree dependency and build state](worktree-setup.md).

After workers release their checkouts, collect and verify their artifacts and integrate accepted work deliberately. Preserve needed unintegrated changes and evidence outside each temporary checkout before removing it. Follow the worktree cleanup playbook through the checkout's proper owner and confirm cleanup completion. Remove local branches only after their needed work has been integrated or preserved. A completed worker alone does not authorize discarding its checkout.

### Working-tree transfer

When a workflow includes uncommitted changes, record the source checkout and its exact HEAD, then create every receiving worktree at that HEAD. Capture the scoped tracked working-tree contents with `git diff --binary HEAD -- <scope>` in a local patch file. This includes the final staged and unstaged contents, additions, deletions, and executable-mode changes. Inventory scoped untracked files separately and copy their file types, bytes or symlink targets, and executable modes to the same relative paths in every receiving worktree. Include ignored input only when the task explicitly needs it. Do not copy the source's Git metadata or unrelated personal state.

Apply the tracked patch in each clean receiving worktree and copy the untracked files before launching its worker. Compare the resulting scoped file bytes, file types, executable modes, and deletions against the source. Record the source SHA, scope, patch, untracked inventory, and comparison result in the brief or its artifacts. If the input changes during capture, recapture a coherent input before dispatch. A diff in the prompt or inherited chat history is context, not this transfer.

For new work that needs a completed worker's built state, give a fresh worker the consolidated brief and reports. Transfer its committed or uncommitted checkout state to an exclusive worktree, or hand over the existing checkout after the prior writer stops. Preserve branch ownership and resource assignments. Reuse the existing worker only under poteto-mode's exception for a costly-to-move checkout, uncommitted changes, a process it still runs, or the conversation of a worker that stopped before its result, per [Continuing a stopped worker](continuation.md). There is no implied copy of a running process. Name the process and host resources if that state is needed.

## Wait, results, and continuation

Track every returned agent or command identity, executor, and slice. For native delegates, use `wait_agent` for an event and `list_agents` for status on runtimes with those tools. The final-answer notification contains the result. Use a result/retrieval tool when the runtime exposes one. A spawn acknowledgement or a completed status without its report is not a result.

For Claude Code, collect the command's terminal receipt and inspect its `result`, `resultEvent`, `sessionId`, `exitCode`, and `signal`, plus the artifacts named by `promptPath`, `requestPath`, `stdoutPath`, `stderrPath`, and `resultPath`. The receipt preserves the process outcome. A failed result's `result` and `resultEvent` text is redacted, and `stdoutPath` keeps the raw stream. Only frames of the named session count. When the stream carries another session's frames, the receipt's `foreignSessionId` names the first one, and the run fails and is not continuable. Review the reported work and artifacts under the calling workflow's normal result and failure rules.

Wait for every required terminal result before synthesis. Record failures and missing reports as gaps under the calling workflow's dropout rule. Review changed artifacts and verification evidence yourself.

Spawns, steering, and continuation remain asynchronous. Use the exposed native controls without inventing a `run_in_background` field, and keep a long-running external command under the host's asynchronous process controls. Collect its terminal receipt later while other independent work proceeds.

Fresh agents take new rounds with the consolidated brief. Reuse an existing agent only for the stateful exceptions in poteto-mode. Before you retry or replace a worker that stopped before its result, read [Continuing a stopped worker](continuation.md). For native delegates, use `send_message` to steer a running agent, `followup_task` to continue an idle agent, and `interrupt_agent` for a stop/hold on runtimes exposing those controls. Use a native resume control only when present. Claude Code's stateful continuation uses its recorded session ID with the runner's `--resume`. Keep a stop order separate from a new work brief.

For a repeated watcher or work that must resume after the active turn, read [Codex loops](codex-loops.md) and use its native event or heartbeat controls.

## Permissions and MCP access

Native v2 delegates use the parent's sandbox, approvals, and available tools. Route the role and its normal task procedures through native delegation. MCP-backed native `recall` investigators and `reflect` delegates use the inherited tools for investigation and citation checks. Claude Code delegates use their existing configured execution environment and receive the same applicable task instructions and source bodies through the runner.
